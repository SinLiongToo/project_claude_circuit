End-to-end production test flow

Manufacturing

This is the whole test flow for the radar SoC, from wafer to vehicle, drawn as one Mermaid flowchart that ties the other pages together. Each box is a test described on the other pages. The flow puts them in production order, with the manufacturing logic that decides the order: protect the hardware first, fail fast and cheaply, respect trim dependencies, stress and then re-measure, and feed every result forward into the next step.

Why this order: the manufacturing logic

PrincipleHow it shows up in the flow
Protect firstCres, open/short and the power-rail short check run before any supply ramps, so a shorted die can't damage the probe card, the tester or neighbouring sites.
Fail fast, fail cheapContinuity, leakage and the scan chain test catch many defects in milliseconds, so they run first. Production uses stop-on-first-fail; characterisation lots use continue-on-fail to collect full data.
Respect dependenciesReferences are trimmed in order (bandgap → aux ADC → temperature sensor → LDOs) before any BIST that measures with them. eFuse is burned once, after memory repair and all trims, then re-read to verify.
Stress, then re-measureIDDQ before and after HVST: a current rise shows a latent defect the stress has activated.
Test at the right temperatureTrims and IDDQ at 25 °C (stable, low leakage). Timing and leakage at 125 °C. Cold final test catches cold-marginal parts (PLL lock, detector offset, hold timing).
Measure RF on-chipRF parametrics use BIST/BISM at wafer, so no mmWave instruments are needed. An RF tester only audits samples, to keep correlation and guard bands honest.
Retest only contact failsContact failures get one re-contact (they are usually probe-card problems). Device failures are never retested until they pass.
Feed data forwardECID links wafer, package, module and field data. Wafer-map screens use sort data, and SPC updates limits, PAT and guard bands over time.

Fail bins

BinCategoryFirst failing testsTypical action
1Pass—Ship
2ContactCres, open (recovers on re-contact)Probe-card maintenance; not a silicon defect
3Short / leakageOpen/short, power short, IIL/IIH, IOZ, IDDQFailure analysis sample; check process and ESD
4LogicScan chain, stuck-at, transition, LBISTDiagnose with scan diagnosis; yield learning
5MemoryMBIST unrepairable, retentionRedundancy analysis; process feedback
6Trim out of rangeBandgap, temperature sensor, detector, LDO trimsCheck against process corner (PCM data)

The order, temperatures and bins are a typical automotive practice for planning. The actual flow is set with the customer, the foundry and the OSAT, and follows the current AEC-Q100 / AEC-Q001 documents.
